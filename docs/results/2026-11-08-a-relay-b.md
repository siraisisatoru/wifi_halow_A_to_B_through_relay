# 2026-11-08: node A → relay → node B on hardware

The full chain on the boards, the same day as the
[root and relay run](2026-11-08-root-relay.md). Test cases are from
[test-plan.md](../test-plan.md).

## Setup

| | Node A | Relay | Node B |
|---|---|---|---|
| Board | Seeed XIAO ESP32-S3 + XIAO WM6108 | MM6108-EKH05 | Seeed XIAO ESP32-S3 + XIAO WM6108 |
| Firmware | node_a, default build (plain STA pinned to `02:48:4C:00:00:02`) | relay_ekh05 | node_b with the root to relay probes on |
| Software | `de9328b`, ESP-IDF 6.0.2, esp-halow `3c46c92`, patches 0001-0003 | `de9328b`, mm-iot-sdk 2.14.3 + patches | as node A |

Radio: AU, REVmf channel list, S1G channel 37 (920.5 MHz), 2 MHz, op class 51, SAE with PMF
required. All three boards were on the same desk, connected to the same laptop. RSSI was -23 to
-33 dBm on both hops, so this says nothing yet about range (T6).

Node B's diagnostic probes (ping and UDP echo to the relay) ran during the whole test, in
addition to node A's traffic.

## Results

| Case | Result |
|---|---|
| T1 path through the relay | **Pass.** A associated with the relay AP 3.1 s after boot (`peer=relay,via_relay=1`). The relay logged `ap_sta_join` for A. B never logged A's MAC as a station (its only station is the relay) but served A's UDP and TCP sessions from 192.168.50.10. |
| T2 steady state (650 s) | **Pass.** See the table below. 0 link drops, 0 TCP reconnects, no unexpected event on any node, heap flat on all three. |
| T3 per-hop latency | **Pass.** Ping A → relay p50 16 ms, A → B p50 29 ms. |
| T7 relay reboot under traffic | **Pass.** Relay halted for flashing at 17:07:48 and booted at 17:08:06.7. A's TCP client detected the stall after 5 s. A's link went down at 17:08:08.5 and its services stopped cleanly. The relay rejoined B 3.9 s after boot, A rejoined via the relay 3.4 s later, services restarted at 17:08:15.2 with TCP connected at the first attempt: 8.5 s from relay boot to traffic. No crash on B (patch 0001 path). |

T2 numbers (node A, from `parse_logs.py`):

| Flow (A →) | Sent | Received | Lost | RTT p50 / p95 / max (ms) |
|---|---|---|---|---|
| UDP echo to B, 10/s × 64 B | 6500 | 6499 | 1 (first second, ARP) | 34.4 / 48.5 / 175 |
| TCP stream to B, 5/s × 256 B | 3250 | 3249 ACKed, 1 in flight | 0 | 35.0 / 48.5 / 62 |
| Ping B, 1/s | 652 | 652 | 0 | 29 / 37 / 173 |
| Ping relay, 1/s | 652 | 652 | 0 | 16 / 25 / 216 |

The maximums are the first packet of each flow, sent while ARP resolved. Heap free at the end: A
271 KB, B 240 KB, relay 56 KB (60 KB before A joined).

For comparison, the host simulation's relay_nominal case predicted UDP p50 22 ms and ping A → relay
about half of A → B. The boards are about 1.5 times slower than the model in absolute terms, with
the same ratio between the hops.

## Observations

- A plain STA (A) noticed the silent relay only after about 20 s (17:07:48 → 17:08:08.5), so
  the TCP client's 5 s stall detection is the first sign of an outage. The relay-STA variant
  (T10) should react faster when the root is lost, but not when the relay itself goes silent.
- B kept the relay's stale association until the relay re-associated (`state=gone` immediately
  followed by `authorized`), as in the earlier run.
